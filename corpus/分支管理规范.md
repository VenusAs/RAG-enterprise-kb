
# 分支管理规范

## 一、分支类型

| 分支名 | 用途 | 生命周期 |
|:---|:---|:---|
| main | 生产分支 | 永久 |
| develop | 开发分支 | 永久 |
| feature/xxx | 功能分支 | 功能完成后删除 |
| hotfix/xxx | 紧急修复分支 | 修复后删除 |
| release/xxx | 发布分支 | 发布后删除 |

## 二、分支操作规范

### 2.1 feature 分支
- 从 develop 切出
- 命名格式：feature/功能名，如 feature/user-login
- 完成后提交 MR 到 develop
- Review 通过后合并，删除该分支

### 2.2 hotfix 分支
- 从 main 切出
- 命名格式：hotfix/问题描述，如 hotfix/order-null
- 修复后同时合并到 main 和 develop
- 合并后删除该分支

### 2.3 release 分支
- 从 develop 切出
- 命名格式：release/版本号，如 release/v1.2.0
- 用于发布前的最后测试
- 发布后合并到 main 和 develop

## 三、合并规范

- 所有合并必须通过 MR（Merge Request）
- MR 必须填写描述、关联 Issue
- MR 必须通过 CI 检查
- 禁止直接 push 到 main 和 develop
- 禁止 force push 到任何共享分支

## 四、版本号规范

遵循语义化版本：MAJOR.MINOR.PATCH

- MAJOR：不兼容的 API 修改
- MINOR：向下兼容的功能新增
- PATCH：向下兼容的 bug 修复

示例：v1.2.3
