
# 需求评审流程

## 一、流程概览

需求提出 → 需求初审 → 需求评审会 → 需求确认 → 进入开发

## 二、各阶段说明

### 2.1 需求提出
- 提出人：产品经理、业务方、客户
- 提交形式：需求文档（PRD）
- 必须包含：背景、目标、功能描述、优先级

### 2.2 需求初审
- 负责人：产品经理
- 时间：需求提出后 1 个工作日内
- 内容：判断需求是否合理、是否重复、优先级

### 2.3 需求评审会
- 参与人：产品、开发、测试、运维
- 时间：每周二、周四下午 2 点
- 时长：每个需求不超过 30 分钟
- 产出：评审结论（通过/修改/驳回）

### 2.4 需求确认
- 产品经理整理评审意见
- 修改 PRD 后发给参与人确认
- 确认后进入开发排期

## 三、评审标准

| 维度 | 要求 |
|:---|:---|
| 需求清晰度 | 无歧义，可执行 |
| 技术可行性 | 开发评估通过 |
| 优先级 | 明确 P0/P1/P2 |
| 工作量 | 明确人天估算 |
| 依赖关系 | 明确上下游依赖 |

## 四、禁止事项

- 禁止跳过评审直接开发
- 禁止评审会上临时加需求
- 禁止需求频繁变更（变更需重新评审）
