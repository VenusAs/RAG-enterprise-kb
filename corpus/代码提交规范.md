# 代码提交规范
## 一、Commit Message 格式

所有提交必须遵循以下格式：

<type>: <description>

### type 类型
- feat：新功能
- fix：修复 bug
- docs：文档更新
- style：代码格式调整（不影响功能）
- refactor：代码重构
- test：测试相关
- chore：构建/工具相关

### description 要求
- 使用中文或英文均可，但同一项目需统一
- 不超过 50 个字符
- 不以句号结尾

### 示例
✅ feat: 添加用户登录功能
✅ fix: 修复订单查询为空的问题
✅ docs: 更新 API 文档
❌ 修改了一下 (缺少 type)
❌ feat: 添加了一个非常非常长的描述... (超过 50 字符)

## 二、提交频率

- 每完成一个小功能就提交，不要攒着
- 每次提交不超过 500 行代码
- 提交前必须运行单元测试

## 三、Code Review 规范

- 所有代码必须经过至少 1 人 Review
- Review 需在 24 小时内完成
- Review 意见必须回复，不得忽略
- 核心模块需 2 人 Review

## 四、禁止事项

- 禁止提交包含密码、密钥的代码
- 禁止提交调试用的 print 语句
- 禁止提交未完成的代码到 main 分支
- 禁止 force push 到 main 和 develop 分支
